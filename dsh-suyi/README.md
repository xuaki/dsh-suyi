# 溯忆 · Anamnesis

> 名字取自两个方向：中文的「溯」，和希腊语的「Anamnesis」。
> 合在一起是一句话：**记得，是为了重新认出你。**

## 为什么叫这个名字

**溯** —— 逆流而上。《诗经·蒹葭》：「溯洄从之，道阻且长。」
去追一件已经发生过的事，从来都不容易。这正是记忆最诚实的样子：不是仓库，是打捞。

**忆** —— 记忆本身。

**Anamnesis** —— 柏拉图的认识论：一切学习都是回忆。
灵魂不是"第一次知道"，而是"重新认出"。这个系统和普通记忆库的区别也在这里：
它不只是存下你说过的话，它要让你在下次听到时能说一句「**我记得**」。

## 一个字的三层意思

| 字 | 意思 | 对应系统里的什么 |
|---|---|---|
| **溯** | 记得来处 | 每条记忆都能追回原始 observation，可溯源 |
| **塑** | 被经历塑造 | 人格的「经验塑造层」，随经历缓慢改变，但改得慢 |
| **诉** | 说得出为什么 | 可解释：能回答「我为什么记得这件事」 |

## 它是什么

DSH 的人格与记忆融合层。分三块：

```
dsl-suyi（本插件：工具 + 自动捕获）
        │  HTTP
        ▼
persona-memory（人格三层 + 证据记忆编排）
        │                    │
        ▼                    ▼
dsh-mnemosyne         Milvus 3.0
（证据链·权威源）      （向量索引·可重建）
```

- **人格三层**：基础人格（只读锚）/ 经验塑造（≥3 条证据才动，单步 ≤0.05）/ 动态状态（15 种分子，分钟级衰减）
- **记忆**：观察 → 候选 → 长期；证据分层（被动 0.15 / 留意 0.4 / 主动 0.7 / 明确 1.0）
- **硬规则**：观察不等于记忆；推断不等于事实；纠正过的永不再作依据

**人格不做权重过拟合。** 过拟合会把人焊死在一个版本上，而且不可更新。
这里用的是「高锚定、低更新速率」——稳，但没死。

## 工具

| 工具 | 什么时候调 |
|---|---|
| `su_recall` | 回答前、需要接上之前聊过的事（默认返回**摘要 + 引用 id**，省上下文） |
| `su_expand` | 拿到 `memory_id` 后展开原文与邻居摘要（链式召回，`depth` 1–2） |
| `su_remember` | 用户说「记住…」，或你判断值得长期留下 |
| `su_persona` | 想知道自己此刻的状态 |
| `su_forget` | 用户说「你记错了」 |
| `su_health` | 排查问题 |

外加 **自动捕获**：每轮对话自动进溯忆，不依赖模型记得调工具——
因为「忘记调用记忆工具」正是长期陪伴最常断的一环。

## 安装

在 `<DSH_HOME>/profiles/<profile>/package.json` 里：

```json
{
  "dependencies": {
    "dsh-suyi": "link:<本插件绝对路径>"
  },
  "dsh": {
    "profile": {
      "bundles": ["...", "dsh-suyi"]
    }
  }
}
```

然后在该 profile 目录 `pnpm install`，重启 DSH。

**不需要手动启动任何服务。** 插件启动时会自己探活，缺哪个就拉起哪个（见下）。

配置（可选，放在根配置的 `dsh-suyi` 下）：

| 键 | 默认 | 说明 |
|---|---|---|
| `base_url` | `http://127.0.0.1:8770` | persona-memory 地址 |
| `auto_capture` | `true` | 是否自动捕获对话 |
| `auto_start` | `true` | 服务不在线时是否自动拉起 |
| `timeout_ms` | `12000` | HTTP 超时 |
| `debug` | `false` | 打印启动/捕获日志 |
| `python` | 推断 | 服务用的 Python 解释器 |
| `mnemosyne_root` / `mnemosyne_data` | 推断 | mnemosyne 目录与数据目录 |
| `persona_root` / `persona_data` | 推断 | persona-memory 目录与数据目录 |

## 服务守护：为什么 DSH 重启不用再手动启动

这里踩过一个坑：最早服务是用 DSH 的后台任务拉起来的，**DSH 一重启，它们就跟着一起被带走**——
每次都要手动重新启动，这不该是用户的活。

现在的做法（`src/bootstrap.js`）：

1. 插件启动时先探健康：已经在跑，就什么也不做（`already-running`）；
2. 缺哪个，用 `detached: true` + `child.unref()` 拉起，**服务脱离 DSH 的进程树**；
3. 服务日志写到 `dsh-suyi/data/<service>.log`。

实测结果：启动器进程退出后，两个服务仍在跑，父进程显示 `<exited>`——是孤儿进程，DSH 再怎么重启都带不走它。

手动检查也可以：

```powershell
node src/bootstrap.js
# [ { "name": "mnemosyne", "state": "already-running" },
#   { "name": "persona-memory", "state": "started" } ]
```

> 注意：`persona-memory` 的代码改动需要重启**服务**才生效（插件只负责让它活着，不负责热更新）。

## 边界

- 记忆服务不可用时，工具会报错而不是假装记得——**宁可说不知道，也不编。**
- 自动捕获只写可见文本，永远不写隐藏的推理流。
- 命名和人格边界仍归用户所有：这个系统只负责「记得」，不负责「决定我是谁」。
