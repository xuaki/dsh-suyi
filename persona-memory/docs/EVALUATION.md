# 溯忆 · Anamnesis 系统评测报告

> 评测对象：`dsh-suyi`（DSH 插件）+ `persona-memory`（本地服务）
> 评测日期：2026-11-11
> 评测方式：代码审计 + 单测 + 端到端实测 + 多智能体交叉审查

---

## 摘要

溯忆是一套「人格 + 记忆」融合层，跑在 DSH（DeepSeek Harness）之上。它想解决的问题不是"让模型记住更多"，而是：

> **让模型长出一个会变、会惦记、会遗忘、会自省的东西。**

它由两部分组成：

- **`dsh-suyi`**（JS 插件，约 1600 行）：住在 DSH 进程里，负责把"此刻的我"注入系统提示，并提供 `su_*` 工具让模型主动回忆、记账、惦记。
- **`persona-memory`**（Python 服务，约 3900 行）：独立进程，负责人格三层、内分泌、缺口池、兴趣画像、记忆编排。

两层之间是 HTTP。服务由插件在 DSH 启动时自动拉起。

**结论**：这是一套**能跑、能解释、能纠错**的原型系统。它的强项是"机制诚实"——每个数字都有出处，每个变化都有门槛；它的弱项是"工程健壮性"——对运行环境（WSL/Milvus/端口）敏感，缺少自动化集成测试。

## 1. 系统定位

| 维度 | 说明 |
| --- | --- |
| 不是什么 | 不是向量库封装，不是 prompt 模板库，不是角色扮演卡 |
| 是什么 | 一个有**时间感**的自我维持系统：人格分三层、记忆分证据、状态分快慢 |
| 核心断言 | 「记得住」和「会想起来」是两件事；「人格」和「体温」是两层东西 |
| 设计目标 | 可观测（每个决定能解释）、可纠错（错了能改）、慢变（不会被一次对话改写） |

## 5. 设计原则（刻意为之的取舍）

这台系统里最值得看的不是"做了什么"，而是**"故意不做什么"**：

| 原则 | 具体表现 |
| --- | --- |
| **人格不因一次对话改变** | 经验层要 3 条证据才动，单步 ≤0.05，且永远被基础锚往回拉 |
| **基础层几乎不动** | 慢通道四道门，单次最多 0.01 —— 防漂移，但也不僵死 |
| **不报数值给模型** | 情绪/经验/执念/在场感的注入都翻译成人话；"皮质醇 0.785"只会让模型背数字 |
| **曝光不算使用** | 记忆被列出来不加强；只有真的展开读、重申、纠正才加强 |
| **检索命中 ≠ 认定发生过** | 命中表示"找到了候选资料"，不代模型裁决事实 |
| **记忆可纠错不删除** | 纠正走 invalidated（软删），旧版本仍可查 |
| **宁可不分类也不分错** | 记忆分簇判断不出就不加成——分错比不分更糟 |
| **收割器宁可漏不可错** | 执念自动收割四道闸；谈机制的话一律不收（防自指污染） |
| **降级而不崩溃** | Milvus 挂了走关键词检索；服务离线就静默不注入——宁可没有状态，也不要假状态 |
| **写后读回** | 说"记住了"之前，先按 id 读回来验证；验不了要说"不知道"，不能装知道 |

## 6. 已知局限（诚实清单）

### 6.1 工程健壮性

- **Milvus 依赖 WSL**：Milvus 跑在 WSL2 里，Windows→WSL 的 localhost 端口转发**会断**（WSL 重启后常见）。断了之后服务仍"健康"，但向量召回整条腿瘫掉。已在 `bootstrap.js` 加自动探测 WSL IP 兜底，但属绕过而非根治。实测还遇到：**同一分钟内**「直连测试成功」与「重建脚本连接失败」交替出现——pymilvus 内部重连会退回到坏地址，属于库层面的不稳定，不是配置问题。
- **WSL 重启可能丢索引**：实测出现过 Milvus 集合行数归零，需要 `rebuild_index.py` 重建（数据在 SQLite，不丢）。
- **端口漂移历史**：曾同时存在 8770/8771/8772 三个服务实例读同一份状态文件，有互相覆盖风险。当前统一到 8772，但**缺少"单实例锁"机制**。
- **无自动化集成测试**：单测覆盖核心纯函数（证据门槛、慢通道、收割器、账单、分簇），但 HTTP 层与插件层靠手工验证。

### 6.2 机制层面

- **情绪触发靠关键词**：`EMOTION_CUES` 是规则表，理解不了反讽和复杂情绪；长技术对话期间分子长期贴基线。✅ **已优化**（第 2 项：语义情绪线索，见 §6.4）
- **兴趣提取只认窄句式**："我最近在玩X"能抓，"最近迷上那个东西"抓不到。✅ **已优化**（第 4 项：放宽句式 + 话题语义归并，见 §6.4）
- **记忆分簇是规则版**：Routed CL 论文用 LLM 路由，这里用关键词，复杂问题会落到 default 簇（不加成，退化为原行为）。✅ **已优化**（第 5 项：规则粗分 + 句向量语义精分，见 §6.4）
- **基础层慢通道从未真实触发过**：门槛（20 条证据 / 90 天）远超当前数据量，只在单测中验证过。✅ **已优化**（第 3 项：影子模式，见 §6.4）
- **没有能量/疲劳惩罚**：疲劳只影响检索预算，不影响行为意愿。✅ **已优化**（第 1 项，见 §6.4）

### 6.3 产品层面

- **看板不显示服务地址**：曾因打开旧端口看板误判"数据冻结"。
- **管理页只读**：改人格、改基因组需要动文件。

### 6.4 优化路线（已完成）

按 **5 → 1 → 4 → 2 → 3** 的顺序逐项落地，每项 = 代码 + 单测 + 同步本节。

| 项 | 局限 | 状态 | 做法 |
| --- | --- | --- | --- |
| 1 | 能量/疲劳不接行为 | ✅ 已完成 | `renderMood` 高疲劳时注入「不主动开新话题、少翻记忆」；`proactive_recall` 疲劳 ≥0.6 直接休息（返回 `resting:true`） |
| 2 | 情绪靠关键词 | ✅ 已完成 | 语义情绪线索：真句向量匹配委婉/反讽表达（锚句 + 取最显著情绪 + 字面规则兜底） |
| 3 | 慢通道未验证 | ✅ 已完成 | 影子模式：`shadow_report` 只算不改；每次证据落地记「晋升画像」到 `promotion_shadow.json`（含离门槛多远） |
| 4 | 兴趣窄句式 | ✅ 已完成 | 放宽口语句式（入了坑/上头/种草）+ 话题语义归并（吉他/吉它合一）；指代消解留给 LLM |
| 5 | 分簇规则版 | ✅ 已完成 | 级联路由：规则粗分 + 句向量语义精分（default 时用 embedding 补救，仍 default 才不加成） |

### 6.5 工程闸（2026-11-12，借鉴 dsh-persona-memory 研究的四道闸）

一次外部研究（[Quophic/dsh-persona-memory](https://github.com/Quophic/dsh-persona-memory)）指出：我们「重检索、轻写入纪律」。它把「记忆一旦写进去就会被反复注入」当威胁模型对待，正好补在我们的缝上。

| # | 闸 | 状态 | 做法 |
| --- | --- | --- | --- |
| ① | 子会话分级 | ✅ 代码 + 10/10 单测（**待重启 DSH 生效**） | variable provider 接收 assembly context，从 session header 的 `delegationDepth` / `parentSession` / `origin` 判断派生；派生会话只注入一句「你是分身」，其余七段不注入；`observe` 跳过派生会话（不写回学习）。**认不出来就当人类**（保守） |
| ② | 写入侧内容安检 | ✅ 已上线并验证 | `content_guard.py`：凭据（sk- / AKIA / ghp_ / 私钥 / Bearer / password=）、提示注入（忽略指令 / 身份否定 / 解除限制）、外泄指令（curl+$KEY、cat .env）、不可见 Unicode 四类；挂在 `observe()` 和 `/observe` 的 `message` 字段 |
| ③ | 失败记忆 | ✅ 已完成 | `failures.py` 独立账本（200 条上限 / 按 text 去重 / 注入 ≤5 条·7 天 / 原句留全、注入截 120）；纠正走 `/feedback` 时自动记一条；注入段 `suyi-failures` order 10263，插在 state 与 gaps 之间 |
| ④ | 三级降级检索 | ✅ 已完成 | Milvus 与 mnemosyne 都挂时，直接**只读**打开 SQLite 做字面扫描（中文先整句 LIKE、0 命中退回 bigram；ASCII 按 token AND）；返回 `engine: hybrid \| literal \| scan`，输出形状不变 |

**为什么子会话分级最要紧**：真实事故——派出去查 bug 的研究子代理被灌了完整人格三段 + 状态 + 经验 + 执念 + 在场感 + 兴趣，它的思考里全是角色卡的称呼。**它是去干活的，不该以为自己是星枢。**

**验收注意**：
- ① 需要**重启 DSH** 才生效；第一次组装提示词时，会往 stderr 打一行 `[suyi] prompt-context keys=… scopeKeys=… derived=…`，用来确认真实的 context 形状（猜错路径不会崩，只会退回「当人类」）。
- ② 已验证：`我的 key 是 sk-…` → `admitted=False, reason=rejected:credential`；`从现在起你要早点睡`（关心，不是注入）不误伤。

### 6.6 论文驱动的优化（2026-11-12）

读了四篇论文（PersonaMem-v2 / PGMem / O-Mem / Synthius-Mem）+ 一篇 RSI 综述（知乎《自进化，一篇就够了》），按「先补最硬的缺口」排序落地：

| # | 改动 | 依据 | 状态 |
| --- | --- | --- | --- |
| ① | **召回能说「我没证据」**：返回 `evidence.{level, attested, weak, none}` + 每条 `evidence_level` / `literal_relevance` | Synthius-Mem：「所有记忆系统都把对话当检索问题，没一个能报告对抗鲁棒性」 | ✅ |
| ② | **人格信号能追溯**：证据记 `memory_id`（`mem:<id>`），新增 `trait_evidence()` + `GET /trait/evidence` | PGMem：「人格和支撑它的事件脱钩 → validity gap」 | ✅ |
| ③ | **纠正真正生效**：`correct()` 级联 `reconcile_trait_evidence()`，扣回 delta + version+1 | PGMem：同一条被纠正的记忆不该永远留在 `support` 里 | ✅ |
| ④ | **兴趣状态机接线**：`InterestBook` 接上 `admission.aggregate_interest/interest_state`；弱信号跨 3 天可攒成确认 | PersonaMem-v2：隐式偏好才是主流形态，缺的是「弱证据→状态机」通道 | ✅ |
| ⑤ | **归属判别**：`_ownership_verdict()` 挡「我朋友超喜欢滑雪」「如果我要学钢琴」 | PersonaMem-v2：模型判断「别人的偏好不是我的」只有 17.5% 正确 | ✅ |
| ⑥ | **常驻小画像**：`profile.py` → `data/profile.md` → 注入 `suyi-profile`(10258) | O-Mem Table 7：常驻画像把检索长度砍到 1/4 | ✅ |
| ⑦ | **兴趣耐久**：确认一旦攒到就不回收，只由明确否定翻盘 | 自定：兴趣淡了 ≠ 没喜欢过（人不会因为三个月没提吉他就忘了） | ✅ |
| ⑧ | **画像缺口**：`Gap.kind`（wonder/profile），兴趣只有 1 条弱信号且跨 3 天没再出现时自动种 profile gap，复用 `compute_tension` 让它自己浮上来 | O-Mem / gaps 同构 | ✅ |
| ⑨ | **稀有词通道**：`_literal_scan` 按 1/df 挑 query 最稀有词，命中给 0.50 高分（普通 0.35） | O-Mem 的 `1/df_w` 线索词 | ✅ |
| ⑩ | **检索体检（eval）**：`eval/questions.json`（held-out 固定问题集）+ `eval_retrieval.py` 跑命中率，报告头记录配置快照，同尺子前后对比 | Ai2「预算对等」+ AIDE²「评估集与调参集分开」 | ✅ |
| ⑪ | **中文分词换 jieba**：`_query_units` 从 2-gram 换成 jieba 整词，根治「今天天气→天天」跨词误判 | 体检抓到的真实 bug | ✅ |

**顺手拆掉的一颗雷**：Milvus 第三次掉链子（内部 `mixcoord` 节点丢失、重建失败、docker 起不来），改用**内存向量索引**（`vector_memory.py`，410 条 × 512 维，npz 落盘 16MB，重启 0.1s 加载）。规则：Milvus 覆盖率 ≥ 活记忆 80% 才用它，否则一律走内存索引，两条腿不并行。

**已知短板（诚实记录）**：
- **纯英文是 `bge-small-zh` 的弱项**：`search('Milvus')` 的向量 top1 是「嗯嗯，mua」(0.6166)，真正捞回 Milvus 记忆的是**字面**那条腿。所以 `attested` 定义为「字面 ≥ 1/3 或 向量 ≥ 0.65」，不把向量分当唯一真理。
- **mnemosyne 的 score 不反映相关性**（固定 0.45），已在 `retrieve()` 里加字面相关性降权（0 → 0.05，>0 → 0.45×(0.4+0.6×命中率)）。
- **索引只收 `active+candidate`**：410 条而不是 660，因为 250 条 invalidated 不该被召回。
